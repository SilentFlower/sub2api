# 修复 OpenAI 流式错误未执行账号停止状态码规则

## Goal

让 OpenAI Responses 流式错误遵守账号已配置的停止状态码规则，余额耗尽时自动停止受影响账号的调度。

## Background

- 用户已选择修复网关代码，明确要求开始修改。
- 请求 `c3008be6-4e3e-409b-8c95-d3307b34dacf` 在 2026-10-29 23:53:43 返回流式 `error`，结构化错误码为 `credit_balance_exhausted`，类型为 `insufficient_quota`，监控归类为 502。
- 只读排查时账号 `3845` 的自定义错误码已开启、列表为 `[502]`，账号仍可调度；该配置的历史生效时刻无法由当前记录确认。
- 已确认代码证据：`backend/internal/service/openai_gateway_passthrough.go:1663` 的流式账号状态分支只覆盖 401、部分 403、429、529；`backend/internal/service/openai_gateway_response_handling.go:577` 的首输出前裸 `error` 还可能绕过账号错误处理。

## Requirements

- R1：账号自定义停止状态码应覆盖流式 `error` 和 `response.failed`，包括首个有效输出之前和之后的终止错误。
- R2：用户现有 `[502]` 配置能够覆盖本次余额耗尽错误，且只停止受影响的上游账号。
- R3：识别结构化余额耗尽错误并正确处理终止与换号资格，保留现有 502 归类和自定义错误码筛选语义；不能通过自由文本猜测账号余额或凭据状态。
- R4：同一次流式失败不能因 `error`、`response.failed` 连续到达而重复写入账号状态；已输出内容后不能重放请求。
- R5：保留现有正常完成、限流、请求级容量/策略/上下文错误的处理；未命中自定义错误码时，不新增账号停用行为。

## Acceptance Criteria

- [x] AC1：以用户错误载荷复现时，启用 `[502]` 的账号被自动标记为不可调度，后续调度排除该账号。
- [x] AC2：原生与透传 Responses 流式路径在首输出前后均覆盖 R1，`error` 与 `response.failed` 组合只应用一次终止失败。
- [x] AC3：自定义错误码未命中、请求级错误及最终成功的流不会被新增逻辑误停；已有 401/403/429/529 行为通过回归验证。
- [x] AC4：新增回归测试与相关现有测试通过，Go 格式和改动检查通过。

## Non-Goals

- 不增加巡检脚本、前端设置、数据库字段或自动充值后恢复功能。
- 本轮代码修改与本地验证不包含生产服务器部署、线上账号状态修改、提交或推送。
