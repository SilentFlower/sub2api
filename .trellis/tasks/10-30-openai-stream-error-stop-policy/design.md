# OpenAI 流式账号停止规则修复设计

## 范围与入口

- 修复 `OpenAIGatewayService` 原生 Responses 和透传 Responses 的 SSE `error`、`response.failed` 终止路径。
- 共用终止判定和账号状态处理的非流式 SSE 转 JSON 路径纳入一致性回归；不重构 WebSocket、Chat、Messages 或全局错误策略。
- 复用现有 `Account`、`RateLimitService`、运行时调度阻断及账号仓储接口，不增加配置、字段或依赖。

## 错误识别与规则契约

- 使用现有结构化错误提取方式识别 `credit_balance_exhausted`；用户载荷中的 `insufficient_quota` 作为已知类型一并覆盖测试，不用英语文案猜测余额。
- 保留这类载荷现有的 502 归类，使已保存的 `[502]` 规则直接生效；不为修复而映射成 429 或 402。
- 流式终止错误进入现有自定义错误码处理，沿用严格布尔开关、列表命中和空列表的既有契约；未开启或未命中时不新增永久停用行为。
- 结构化余额耗尽属于账号上游失败，可在首个有效输出前进入已有换号机制；停止状态码仍只决定账号状态处理，不单独决定是否重试。
- 更新账号状态仍由 `handleOpenAIAccountUpstreamError` 接入 `HandleUpstreamError`、`SetError` 与运行时阻断，避免仅落库而调度缓存继续使用账号。

## 终止事件与时序

- 原生和透传读取器必须覆盖首输出前的裸 `error`，不能只修改后半程账号状态 helper 而漏掉其调用入口。
- 对支持裸错误后续权威终止事件的现有路径，保留延迟处理：后续 `response.failed` 或裸错误 EOF/超时终结时应用一次；后续成功终止保留成功语义。
- 已有有效输出时保留当前流，不重放请求；处理失败账号状态时仍继续提取权威终止事件的 usage。
- 复用现有事件状态标记和失败收口，避免新增全局去重表或跨请求状态。

## 兼容性与排除

- 保留 401、凭据级 403、429、529 的现有行为和优先级。
- cyber、上下文超限、参数/内容策略、请求级容量降载仍按各自现有规则处理，不能因监控兜底显示 502 而被误判为账号故障。
- 保留已配置的临时不可调度等策略优先级，复用既有账号错误入口，不新增另一套状态写入路径。
- 保持上游错误诊断、响应形态及用量提取；不记录请求正文、真实密钥或登录凭据。

## 验证与交付边界

- 测试覆盖用户错误载荷、原生/透传、首输出前后、单独错误/错误后跟失败/错误后成功、配置命中与未命中，以及运行时调度阻断。
- 优先新增独立的 `openai_stream_error_policy_test.go`，复用现有测试辅助；必要时为共用非流式 SSE 转 JSON 补一致性用例。
- 本轮交付是代码和本地验证证据。重新构建镜像与生产部署另行执行；本轮不连接服务器改状态。
- 回滚以本次代码差异为边界，不需要数据库迁移或配置回滚。
