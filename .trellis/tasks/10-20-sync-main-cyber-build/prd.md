# 同步最新 main 并移植 cyber 会话隔离修复到 build

## Goal

将本仓库最新 main 与用户指定 PR 的 cyber 会话隔离修复纳入 build，保留双方能力，并先提供有代码依据的冲突处理与完整回归方案供用户审阅。

## Background

- 用户明确要求“先给方案”，包括文本冲突、处理方法以及无冲突部分的双方功能正常。
- 原 build 为 `f03c930bef832df4d49c90de0e895316e7ffc1fd`（0.2.11），最近一次同步的共同基线为 `42bc7f6cffe24bcb471608e48e66b4a0afa1f882`。
- 本轮已获取并快进本地 main 到 `8f2cbb53d9d1c40e1865b07ac460571f7d4c48de`（0.2.17）；末次远端核对没有漂移。
- 用户指定修复为 `xlplbo/sub2api#1`，已在该 fork 合并。其修复提交为 `14ba46df4fccf60a4f960befcc4c930d8d0cd7b1`，源自 `Wei-Shaw/sub2api#6834`。
- 线上问题已确认包含本地 `transcript_lookup_limit_exceeded` 拒绝；单次解封已经按此前授权独立完成，不属于本次代码合并。

## Requirements

- R1：在实施前展示可重复的合并预演、全部文本冲突和逐项解决方案，输入变化时刷新方案。
- R2：同时保留 main 新增及修复行为与 build 实际私有能力；覆盖共同修改、独立文件及跨层入口，不只审查 Git marker。
- R3：独立会话不因共享 API Key、IP、客户端、缓存 key 或历史长度而被推断封禁；同一真实命中会话仍可按明确 ID 屏蔽，不同 API Key 相互隔离。
- R4：实际上游安全拒绝继续透传、审计和按真实用量记账；白名单及 HTTP/WS 的原有相关行为保持，无明确会话 ID 的新行为在方案中清晰说明。
- R5：保留 build 的搜索、引用、混合工具、Lite、Schema、推理、Grok、GIF、模型提示词、超时及计费能力，并使其适配 main 的统一路由和新模型契约。
- R6：新旧账号/系统设置均可创建、编辑、保存并正确回显；中英文界面及最终覆盖文案保持完整。
- R7：数据库迁移、生成代码、依赖工具链与分支工程/部署资产有明确验证和回退边界；不得修改旧迁移或误触业务数据。
- R8：最终结果以实际测试/构建/检查证据交付；区分新回归、原有失败和未覆盖场景，不把自动合并或源 PR 自述当作功能正常证据。
- R9：先展示方案，用户审阅确认后实施真实合并；提交、推送触发镜像发布、生产部署及真实数据操作另按交付边界处理。
