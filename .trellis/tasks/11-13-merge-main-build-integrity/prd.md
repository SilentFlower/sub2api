# 合并远程 main 到 build 并验证双方功能完整性

## Goal

将当前远程 main 的更新整合到 build，解决文本与语义冲突，让上游改进和 build 既有功能按项目契约共同运行。

## Background

用户要求拉取远程 main，查看并处理合入 build 的冲突，同时保障自动合并区域的双方功能。预演基线与逐文件清单见 research/merge-preview.md。已确认 32 个冲突文件、100 个双方修改文件。Flower 0.6.13-beta.13 升级的 19 个文件属于实施前已存在的独立改动。

## Requirements

- R1：整合固定远程目标 530c5e3a4。保留 build 自身历史与功能，不通过整仓选择一侧解决。
- R2：逐个处理 32 个文本冲突，逐个复核其余 68 个双方修改且自动合并的文件；额外检查单边新增实现接入、生成代码和迁移的兼容性。
- R3：保留 build 的 Responses Lite、Fast、搜索与引用、协议桥接、超时分档、账号 extra 与渠道配置、cyber 明确身份隔离及流式错误停调行为。
- R4：接入 main 的新模型支持、计费与 cache-write TTL、资源约束、会话缓存、新管理能力和修复，保持对应测试与跨层字段一致。
- R5：已有项目明确约定优先于历史上游行为。cyber 保留 v2 明确会话 ID + API Key 语义；main 的 transcript 改进按此边界处理。确有业务语义互斥且规范未裁决时，记录差异并提交用户决定。
- R6：中英文最终聚合树、静态翻译调用与覆盖后的有效文案完整；配置默认值、环境变量、校验和 Compose 接线完整。
- R7：提供真实验证命令、结果、覆盖范围和未验证项。验证采用本地环境，数据库迁移进行静态与隔离环境检查。

## Acceptance Criteria

- A1（R1、R2）：合并工作区的冲突全部解决，冲突清单和自动合并交集清单逐项有结论；合并提交的执行另遵循 Git 审阅门槛。
- A2（R3、R4、R5）：协议转换、模型策略、cyber 隔离、搜索引用、停调与计费的上游和 build 回归测试通过；发现的交互回归有专项行为断言。
- A3（R6）：前端 lint、typecheck、Vitest、生产构建和四项 locale 契约测试通过；账号编辑与渠道保存保留双方新增键。
- A4（R4、R6）：后端编译、unit 和 lint 通过；Ent/Wire 源定义及生成物一致；配置、部署示例和迁移检查通过。
- A5（R7）：检查报告区分已通过、失败和未验证范围。涉及外部服务、凭据和数据库的场景写明环境需求与风险。

## Non-Goals

- 生产发布、生产数据库变更、真实上游付费调用。
- 无关业务重构与额外产品功能。
- 自动批准提交或远程推送；Git 动作进入独立精确计划确认。
