# 同步 main 0.2.11 到 build 并保留定制功能

## Goal

将已获取的 main 0.2.11 更新合入 build，保留当前定制功能，并通过冲突处置和跨路径回归确认合并后的功能正常。

## Background

- 原始需求：拉取 main 最新代码到 build，关注冲突，也保证无冲突区域功能正常，先给出冲突处理等预览方案。
- 用户已确认预览并要求任务跟踪：`确认吧我们任务跟踪吧`。完整预览固化于 `research/approved-preview.md`。
- 当前 build 为 `9c914278cef7cfe571120d19a92b7a75e5bfc6f8`；固定 main 为 `42bc7f6cffe24bcb471608e48e66b4a0afa1f882`；共同基线为 `a3eb7ef302961cba716dc78b39b93b60c467db0e`。
- 待合入 126 个提交，上游净改动 268 个文件；双方共同修改 71 个文件，其中 10 个文件有 13 个冲突块，61 个文件可自动合并。
- 规划阶段仅完成预览静态检查；实施阶段已实际执行固定 SHA 的未提交 merge、解决 10 个冲突并复核 71 个共同文件。实际验证结果见 `research/validation.md`，当前未提交、推送或部署。

## Requirements

- **R1 上游能力完整**：接入固定 main 的新模型、余额在途预占、API Key 创建限制、渠道图片价格继承、风控白名单、Claude 重置和账号配置等更新。保留上游默认行为：预占开启、TTL 900 秒、活动 Key 上限 200、每小时创建上限 60。
- **R2 当前定制保留**：保留 build 的模型提示词、粘性会话、Grok 配额、Lite 开关和 blocked models、混合工具及本地搜索、Schema 降级、当前 DeepSeek reasoning 回注、图片桥接及配置、非流式 header timeout、Ollama token 上限、模型映射与合成分组、定制账号字段和现有工程资产。以当前源码为准，不恢复已删除的历史功能。
- **R3 协议与计费一致**：搜索必须同时保留真实搜索证据与成功完成判定；适用时可进入现有本地模拟回退。工具参数首事件与后续 delta 不产生重复 JSON；显式关闭推理不得被模型后缀重新开启；计费 effort/tier 依据最终实际出站请求。
- **R4 自动合并语义安全**：61 个自动合并的共同修改文件逐一复核接口、调用顺序、配置往返、生成代码和测试预期，同时检查上游独立文件与 build 独立领域文件的契约。前端新增设置与定制字段并存，最终中英文文案完整。
- **R5 补齐已确认接入缺口**：本次同步一并补接 Messages -> Chat 的现有 Ollama token 裁剪 helper，与 raw Chat、Responses -> Chat 保持一致；测试断言实际出站请求，避免只验证入站参数。
- **R6 可回退、可审计**：保留原 build 的三个本地工程提交和恢复基线，记录每项冲突处置、验证命令及结果；明确区分文件保留、静态检查、行为测试和未覆盖的真实上游场景。

- 不追入固定 main 之后的新增提交，不同步 `other` remote。
- 不执行业务数据库迁移、线上数据操作、付费模型请求或真实 Claude 重置。
- 不做无关重构，不改写分支历史，不恢复已移除功能。
- 本轮实现不自动提交、推送或部署；验证通过后展示实际结果，再进入对应流程。
