# 为 OpenAI 图片和非流式文本设置独立响应头超时

## Goal

避免正常的图片生成、图片编辑和非流式文本请求被生产环境统一的 20 秒上游响应头等待时间提前截断，同时保留流式文本请求的快速失败策略。

## Background

- 2026-09-24 13:54:20 的 `/v1/images/edits` 请求 `1d01614e-dd29-4f85-83ae-aeabd47c27c0` 在等待上游 HTTP/2 响应头约 21.5 秒后收到本站 502；上游没有返回 HTTP 状态码。
- 生产容器当前 `GATEWAY_OPENAI_RESPONSE_HEADER_TIMEOUT=20`。同一账号相邻请求也在约 22.1 秒后以相同错误结束。
- 生产数据库当前没有启用 OpenAI OAuth 插件绑定；事故请求不经过插件传输。
- 当前图片上游请求使用通用 OpenAI 传输配置，响应头等待时间无法按图片或非流式文本请求独立设置。

## Requirements

- R1. OpenAI `/v1/images/generations` 和 `/v1/images/edits` 的同步与流式请求使用独立的上游响应头超时，默认 600 秒。
- R2. OpenAI `/v1/responses`（含该 handler 的 compact 兼容路径）和 `/v1/chat/completions` 的非流式文本请求使用另一项独立的上游响应头超时，默认 300 秒。判定依据是客户端入站请求的 `stream` 语义，而不是桥接后的上游传输形式。
- R3. OpenAI 流式文本请求继续使用现有 `GATEWAY_OPENAI_RESPONSE_HEADER_TIMEOUT`；生产环境保持 20 秒。图片请求优先于非流式文本规则。
- R4. 两项新超时支持部署配置覆盖；不同超时的请求不能误复用同一个 HTTP 客户端配置。仅 OpenAI 平台账号适用新分档；其他平台的代理、HTTP/2 容错、认证、响应和计费语义保持一致。
- R5. 完成代码验证后，按生产部署方式更新服务，并核对运行配置与健康状态；不通过真实付费生成请求制造验证流量。

## Out Of Scope

- 其他平台、WebSocket、Embedding、模型目录、账号测试和后台探测的超时策略。
- HTTP 响应头之后的流式数据间隔超时、下游客户端超时和代理超时策略。
- 修改生产环境现有的 20 秒通用 OpenAI 超时值。

## Acceptance Criteria

- [x] A1. 两个图片端点的上游 HTTP 客户端响应头超时均为 600 秒，且不受通用 OpenAI 20 秒配置截断。
- [x] A2. 两个文本端点在 `stream=false` 时使用 300 秒，在 `stream=true` 时继续使用通用配置；缺省 `stream` 按现有非流式语义处理。
- [x] A3. 相同账号和代理下，不同超时策略拥有可稳定复用且互不覆盖的连接池；原有 HTTP/2 回退与代理路由仍生效，其他平台不被分入新超时类别。
- [x] A4. 新配置可读取、校验和覆盖；现有错误响应、日志和计费行为无意外变化。
- [x] A5. 聚焦测试通过；生产应用更新后，新配置生效、容器健康，且旧通用超时仍为 20 秒。
